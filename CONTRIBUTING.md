# 📜 Правила для участников проекта
Раз вы сюда заглянули, значит вам интересно развивать этот проект
## 🛠️ Требования к окружению
Это все, что нужно обязательно 100%, прям точно:
- Java 25
- JDA 6.х.х (Java Discord Api)
- Gradle -> `./gradlew`
- PostgreSQL

## 🚀 Как внести что-то свое?
1. **Создайте форк (Fork)** этого проекта
2. Клонируйте проект к себе - `git clone https://github.com/KiKaaad/smllyBot.git`
3. Создайте ветку dev - `git checkout -b dev`
4. Протестируйте приложение
5. Запушьте изменения в свою ветку dev
6. Создайте Pull Request в dev ветку нашего репозитория.
Не забудьте описать, что нового вы сделали и следовать шаблону запроса на слияние

## 🌳 Ветки проекта
В проекте есть всего 2 основные ветки:
- **main** - в нее вливаются все проверенные на 99.9% коммиты. Основная и релизная
- **dev** - "горячая" ветка. В нее вливаются все сырые изменения в проекте, которые позже через Pull Request будут влиты в основную ветку после проверки кода.

## 🐛 Я нашел баг! Как создать issues?
- Укажите верный тег для вашей проблемы и озаглавьте проблему правильно
  - ❌ **НЕ ТАК:** Это очень серьезная проблема
  - ✅ **ТАК:** Неверное форматирование текста в module
- Как можно подробнее опишите проблему: Логи, как эта проблема возникла, как ее можно воспроизвести и подобное.
- Какой результат ожидали и какой получился

## 🖋️ Как оформлять коммиты:
Эмоджи необязательны, но с ними удобнее писать чендж-логи. Их также можно изменять, только так, чтобы они были логически верны коммиту.
`<тип>[область]: [Описание]`
- ✨ **feat** — Новая фишка, функциональность, логика
- 🐛 **fix** — Исправление багов
- 📝 **docs** — Изменение документации
- 🎨 **style** — Изменение стиля кода, не влияющие на функциональность\
  **Пример:** Убрал точку с запятой в коде котлина. Изменил название метода на более логичное
- 🔄️ **refactor** — Изменение кода, не влияющие на функциональность\
  **Пример:** Супер длинный код базы данных на 200 строк был уменьшен до 100, при этом он выполняет ту же функцию! Чудо
- 🖇️ **chore** — Обновление зависимостей

Примеры коммитов:\
`✨ feat(ban): Добавлена возможность блокировать пользователя`\
`⚡ refactor(database): Увеличена производительность базы данных за счет перехода с Hibernate на JDBCTemplate`

## 📝 Как оформлять чендж-логи:
Эмоджи также необязательны, но так удобнее. Более того, они пишутся в основном для людей, не разбирающихся в коде бота\
Вы также вправе использовать полные возможности markdown, чтобы сделать чендж-лог как можно более удобным
```markdown
# v<версия> (ДАТА)
## ✨ Новое
- <Что нового> `может это команда`
## 🔄️ Изменено
- <А что изменилось>
## 🐛 Исправлено
- <Что было исправлено>
## 📝 Документация
- <Какие-то правки в документации>
```
